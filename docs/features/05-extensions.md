# 05 — Extensions: GFM, footnotes, math, Mermaid (phase 6)

*Phase 6 of the roadmap in `features/markhippo-design-spec.md` (§3.2): the
extensions, added one by one as plugins. Each is its own plugin and can be
switched off under Plugins.*

## The plugins

| Plugin | Syntax | HTML | Source |
|---|---|---|---|
| `tables` | pipe tables with a delimiter row and `:` alignment | cmark-gfm's `<table><thead>…` | `plugins/gfm/tables*.js` |
| `task-lists` | `- [ ]` / `- [x]` at an item's start | `<input type="checkbox" disabled="" />`, live in the app | `plugins/gfm/task-lists.js` |
| `strikethrough` | `~one~` / `~~two~~` | `<del>` | `plugins/gfm/strikethrough.js` |
| `autolinks` | bare `www.`, `http(s)://`, `ftp://`, emails, `mailto:`, `xmpp:` | `<a>` | `plugins/gfm/autolinks.js` |
| `tag-filter` | `<script>`, `<style>`, `<iframe>`… in raw HTML | the `<` escaped | `plugins/gfm/tag-filter.js` |
| `footnotes` | `[^label]` and `[^label]:` blocks | cmark-gfm's `footnote-ref` and `<section class="footnotes">` | `plugins/footnotes/` |
| `math` | `$…$`, `$$…$$`, `$$` blocks, ```` ```math ```` | `<span/div class="math …">` with the TeX, then MathML | `plugins/math/` |
| `mermaid` | ```` ```mermaid ```` | `<pre class="mh-mermaid">` with the source, then SVG | `plugins/mermaid/` |

**Conformance.**
- `test/gfm.test.js` runs the GFM examples, 54 in all, generated by
  `make gfm-fixtures`:
  - the GFM spec's extension examples (tables, task lists, strikethrough,
    autolinks, tag filter);
  - cmark-gfm's own `extensions.txt` (more tables, autolinks, footnotes,
    interop).
- All pass. Task list checkboxes are compared with their attributes in
  either order, because the GFM spec writes GitHub's markup and cmark-gfm
  its own.
- With every extension on, the CommonMark 0.31.2 suite changes only in its
  Autolinks and HTML blocks sections, where GFM means it to: bare URLs link,
  and disallowed tags are escaped.

## New plugin seams

These were added to the API (`core/registry.js`) because the extensions
needed them. Third-party plugins can use them too.

- **`api.inlineFinisher(fn)`**
  - `fn(state, block)` runs on each leaf after its inlines are parsed and
    merged.
  - The GFM autolinks plugin uses it to find bare links in plain text: only
    text whose source is exactly its literal, so offsets map one to one, and
    never inside links, images or code.
  - Doing this afterwards keeps letters from becoming inline triggers, which
    would slow every text run.
- **`api.enhancer({ selector, run(elements, context) })`**
  - Finishes the rendered preview in the browser, after the HTML is
    sanitized and in place (`enhance.js`, from `PreviewView`'s `onUpdate`).
  - The parser and renderer never run enhancers, so plugins stay pure and
    testable in node.
  - Exported HTML keeps the plain fallback: the TeX, or the diagram's
    source.
  - `context` is `{ dark }`.
  - Enhancers cache, so a re-render while typing is synchronous and doesn't
    flicker.
- **`definition: true` on a block rule.** Incremental reparse treats such
  nodes like link reference definitions: if the definitions in the reparsed
  region change, it parses in full.
- **The reference map carries footnotes.** It holds them under keys a link
  label can never produce (a NUL, which the parser replaces in source). A
  region reparse therefore resolves references to footnotes defined
  anywhere.
- **Renderer options:**
  - `taskAttribute` names the attribute a live checkbox carries its source
    offset in.
  - `sourceLines` can name its attribute (phase 5's review fix).

## Notes per extension

**Tables** (`tables-parse.js`)
- The delimiter row is a block start tried while a paragraph is open, like
  a setext underline.
  - The paragraph's last line becomes the header. Anything before it stays a
    paragraph.
  - The cell counts must match.
- The table takes lines (`acceptsLines`) until a blank line or a line that
  starts another block.
  - Each line becomes a `table_row` of `table_cell` leaves as it is added
    (`lineAdded`).
  - Rows are cut or padded to the header's width.
- `\|` loses its backslash before inline parsing, even inside code spans.
  Cells keep segment maps across the removed backslashes, so inline
  positions are still exact.

**Task lists**
- An inline rule on `[`, ahead of the link opener, matches only at the
  start of an item's first paragraph.
- In the app the checkbox is live. Clicking it toggles `[ ]`↔`[x]` in the
  source through an undoable edit that leaves the caret, scroll and focus
  where they were (`EditorView.editAt`).

**Footnotes**
- A container block; continuation lines are indented four spaces.
- References render only where defined; `[^nope]` stays text.
- Numbering, backrefs (`fnref-x-2`…, `↩<sup>2</sup>`) and the section at the
  end come from the plugin's `document` renderer.
- Labels in ids are percent-encoded, as cmark-gfm does, which also defuses
  `[^"><script>]`.

**Math**
- An inline `$` must hug its content, with no digit after the closing one,
  so `$5 and $6` stays money.
- **Temml** (vendored, MIT) turns TeX into MathML, which the browser draws
  natively.
  - Only `Temml-Local.css` and its one font are added to the page.
  - Temml's `trust` stays off, so `\href` and friends are disabled.

**Mermaid**
- **Mermaid 12** (vendored, MIT): the ES build plus its code-split chunks,
  5.4 MB on disk.
  - Only the core and the chunks for the diagram types a document uses are
    fetched, and only once a document has a diagram.
- It runs at `securityLevel: "strict"`: no scripts or click handlers, and
  labels as text.
- Diagrams use Mermaid's `dark` theme in dark mode and `default` otherwise.
  They are redrawn when the resolved mode changes.
- A failed diagram shows Mermaid's parse error above its source. Mermaid's
  leftover scratch element is removed.

## Security

- The page's CSP now allows inline styles, because Mermaid's SVG is styled
  with them.
  - To keep documents from restyling the page, the preview sanitizer removes
    every `style` attribute (and, as before, `<style>` elements) from the
    rendered HTML before enhancers run.
  - Only MarkHippo's own enhancers add styled content.
- Scripts remain `'self'` only.
- The vendored libraries are loaded from `src/vendor/` on this origin; no
  CDN is used, so it all works offline. `make vendor` refreshes them from
  npm at the pinned versions in the `Makefile`. Their licences sit beside
  them and in `NOTICE`.

## Editor, outline and suggestions

- **Colours.** Every extension colours the edit pane: table pipes and the
  delimiter row as markup, header cells bold, task markers, struck text,
  footnote labels, math. Mermaid sources are coloured as a language of
  their own.
- **Suggestions:**
  - Block (`/`): Table, Task list, Footnote definition, Math block, Diagram.
  - Inline: Strikethrough, Footnote, Math.
  - Fence languages: `math`, `mermaid`.
- **Minimap.** Draws the new tokens in their colours.
- **Sample.** The sample document gained a "Beyond CommonMark" section that
  shows each extension.

## Tests

`test/gfm.test.js` covers:

- the GFM examples;
- CommonMark interference;
- row splitting and cell positions, including inside block quotes;
- where task markers may appear;
- live checkboxes;
- no autolinks inside links, images or code;
- footnote numbering and incremental reparse with footnotes;
- math and Mermaid markup;
- the enhancer registrations;
- the suggestions;
- highlighting well-formed on every example;
- an incremental-equals-full fuzz with every extension on.

Checked by hand in Chrome (the sample document):

- table, task list, strikethrough and footnote render;
- inline and display math as MathML;
- the Mermaid flowchart in both themes, and a broken diagram's error;
- ticking a task updates the source;
- no console errors or CSP violations.
